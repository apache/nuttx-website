nvmpg-stm32f1

Tags: arch:arm chip:stm32f1 part:stm32f103 vendor:st

The NVMPG is a hand-held MPG (Manual Pulse Generator) pendant made by Digital Dream for its NVUM, NVEM, EC300 and EC500 CNC motion controllers. It has a handwheel, ten push buttons and a 2.0” color TFT display that shows the axis positions, the feed/spindle/jog overrides and the MPG step that the controller reports over a serial link.

Inside it there is an STM32F103RCT6 that drives the display, scans the keys and talks to the controller. The handwheel encoder and the E-stop are not connected to the MCU: they are wired straight through the cable to the controller.

This port replaces the original firmware. The dro configuration speaks the same serial protocol, so the pendant keeps working with the controller.

Features

  • STM32F103RCT6: Cortex-M3, 256 KiB of FLASH and 48 KiB of SRAM

  • ILI9225 176x220 RGB565 TFT display on a 16-bit 8080 parallel bus, used in landscape mode (220x176)

  • 10 push buttons

  • USART1 link to the CNC controller (115200 8N1)

  • SWD debug interface

Note

The display bus is driven by bit-banging GPIOs (GPIOB is the 16-bit data bus), not through the FSMC, because the STM32F103RC in its 64-pin package has no FSMC. The upstream drivers/lcd/ili9225.c driver only supports SPI, so this board provides its own lcd_dev_s implementation in src/stm32_ili9225.c.

Buttons and LEDs

There are no user LEDs.

The ten buttons are active-low inputs with external pull-up resistors. They are registered as /dev/gpio0 .. /dev/gpio9 (CONFIG_DEV_GPIO) and polled by the application: PA0-PA3 and PC0-PC3 share the same EXTI lines, so they cannot all be used as interrupt buttons.

Serial Protocol

The pendant is a slave of the controller. All the information on the display comes from the controller, and the pendant only reports key events. For instance, pressing the Step key sends 0x05; the controller then changes the MPG step and reports the new value back, and only then the display changes.

Controller to pendant:

  • 5A 5A followed by a 51-byte status frame (no checksum).

  • 5A 5B: identify request. The pendant answers 01 13.

The LCD reset line is not connected to the MCU. PB3 and PB4 are only usable as GPIOs with JTAG-DP disabled, so the board is configured with CONFIG_STM32_JTAG_SW_ENABLE (SWD only).

Power Supply

The pendant is powered with 5 V by the controller through the MPG cable.

Clock

The original firmware clocks the PLL from HSI/2, so it is not known for sure which crystal is fitted to the board. By default the port does the same (HSI/2 x 16 = 64 MHz), which works whatever crystal is fitted.

  • CONFIG_NVMPG_STM32F1_HSE_8MHZ: clock the PLL from an 8 MHz HSE crystal instead, for a 72 MHz system clock.

Installation

The toolchain and build environment are the same as for the other STM32F1 boards; see Installing.

Building NuttX

$ ./tools/configure.sh nvmpg-stm32f1:dro
$ make

Flashing

The board is programmed through SWD (PA13/PA14) with an ST-Link probe and OpenOCD:

$ openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
    -c "program nuttx.bin 0x08000000 verify reset; shutdown"

ST-Link clones with old firmware (older than V2J24) only work with the interface/stlink-hla.cfg interface script.

Warning

Back up the original firmware before flashing NuttX, for instance with dump_image nvmpg-original.bin 0x08000000 0x40000 from OpenOCD, if you want to be able to restore it later.

The board configuration sets DBGMCU_CR.DBG_SLEEP at boot, so the debugger can attach to the running firmware even while the CPU is sleeping in the idle loop.

Configurations

$ ./tools/configure.sh nvmpg-stm32f1:<config-name>

dro

Replacement firmware for the pendant. It starts the nvmpg-dro application directly (CONFIG_INIT_ENTRYPOINT="nvmpg_dro_main"). There is no NSH console: USART1 is used for the link to the controller (/dev/ttyS0).

At power up the NuttX logo is shown for one second, then the DRO screen: the axis positions, the FRO/SJR/SRO overrides, the MPG step, and the RESET and COMM lamps. The positions are drawn in grey when no frame was received from the controller for one second.
