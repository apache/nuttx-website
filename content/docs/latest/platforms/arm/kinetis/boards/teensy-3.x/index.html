teensy-3.x

Tags: arch:arm chip:kinetis vendor:nxp

The Teensy 3.1 and 3.2 are compact, breadboard-friendly development boards designed by PJRC (Paul Stoffregen), powered by the NXP (formerly Freescale) Kinetis MK20DX256VLH7 ARM Cortex-M4 microcontroller.

This board configuration also supports the earlier Teensy 3.0 board (which features the Kinetis MK20DX128VLH5 microcontroller).

Note

The initial port of NuttX to the Teensy 3.1 was contributed by Jakob Odersky (jodersky).

Hardware Overview

Warning

While digital I/O pins on the Teensy 3.1/3.2 are 5V tolerant, the analog inputs (A10, A11, AREF, and the internal ADC reference) are strictly 3.3V maximum. On the Teensy 3.0, all pins are 3.3V only. Exceeding 3.3V on non-tolerant pins will permanently damage the microcontroller.

Key Features (Teensy 3.1 / 3.2)

  • Microcontroller: NXP Kinetis MK20DX256VLH7 (64-pin LQFP) - 32-bit ARM Cortex-M4 running at 72 MHz (overclockable up to 96 MHz) - 256 KB Flash memory, 64 KB SRAM - Hardware CRC and Random Number Generator

  • Clocking: - 16 MHz external crystal (XTAL on PTA18/PTA19) - On-chip PLL generating 72 MHz system clock (or 96 MHz when overclocked)

  • USB Interface: - Full-Speed (12 Mbps) USB 2.0 Device/Host/OTG port with Micro-B connector - Dedicated USB regulator providing 3.3V (up to 100 mA) to external circuits

  • Serial Communication: - 3 UARTs with FIFO and hardware CTS/RTS support - 2 SPI modules with FIFO - 2 I2C modules with SMBus support

  • Analog & Timers: - 2 16-bit ADCs with differential mode support - 1 12-bit DAC - 3 FlexTimer modules (FTM) supporting up to 12 PWM channels - Carrier Modulator Transmitter (CMT) - Real-Time Clock (RTC) with external 32.768 kHz crystal footprint

  • Form Factor & Bootloader: - 24-pin DIP footprint (0.1” pitch, breadboard friendly) - Onboard Nuvoton Mini54TAN processor running PJRC HalfKay USB bootloader - Pushbutton for entering bootloader mode

The default serial console in the nsh configuration is UART0 on:

  • RX: Pin 0 (PTB16)

  • TX: Pin 1 (PTB17)

  • Baud rate: 115200 8N1

Connect a 3.3V USB-to-UART serial adapter (TX to Pin 0, RX to Pin 1, GND to GND) to access the NuttShell prompt.

Flashing and Debugging

Using the Teensy Loader

The Teensy 3.x comes pre-programmed with PJRC’s proprietary HalfKay bootloader managed by the onboard Mini54TAN chip. The bootloader communicates over USB via the Teensy Loader application or the command-line tool teensy_loader_cli.

NuttX configurations for the Teensy 3.x enable Intel HEX binary generation (CONFIG_INTELHEX_BINARY=y), which produces nuttx.hex in the root directory after compilation.

Flashing with teensy_loader_cli:

  1. Install teensy_loader_cli on your host system:

    # Ubuntu / Debian
sudo apt-get install libusb-dev
git clone https://github.com/PaulStoffregen/teensy_loader_cli.git
cd teensy_loader_cli && make && sudo make install

  2. Build NuttX and upload the generated nuttx.hex:

    # For Teensy 3.1 / 3.2 (MK20DX256):
teensy_loader_cli --mcu=mk20dx256 -w -v nuttx.hex

# For Teensy 3.0 (MK20DX128):
teensy_loader_cli --mcu=mk20dx128 -w -v nuttx.hex

  3. Press the pushbutton on the Teensy 3.x board to initiate the programming cycle. Once flashing completes, the board reboots into NuttX automatically.

Hardware Debugging (SWD / JTAG)

Standard hardware debugging via SWD is not directly available out of the box because the onboard Mini54TAN bootloader chip controls the Reset and SWD lines of the K20 microcontroller.

To use an external SWD debugger (such as J-Link, ST-Link, or CMSIS-DAP), the hardware traces between the Mini54TAN and the MK20 chip must be severed or the Mini54TAN held in permanent reset. For detailed instructions on this modification, refer to the Hacking the Teensy 3.1 for SWD Debugging guide on MCU on Eclipse.

Supported Configurations

The board configurations for the Teensy 3.x are located under boards/arm/kinetis/teensy-3.x/configs/.

nsh

The default NuttShell (NSH) configuration provides an interactive command-line interface over the primary serial port.

  • Console: UART0 (Pin 0 RX, Pin 1 TX) at 115200 8N1

  • Binary formats: Raw binary (nuttx.bin) and Intel HEX (nuttx.hex)

  • Builtin applications: Enabled

Building:

./tools/configure.sh teensy-3.x:nsh
make -j$(nproc)
teensy_loader_cli --mcu=mk20dx256 -w -v nuttx.hex  # Use --mcu=mk20dx128 for Teensy 3.0

usbnsh

Configures the NuttShell console to run over the native USB port using the USB CDC/ACM class driver (virtual COM port).

  • Console: USB CDC/ACM (/dev/ttyACM0 on Linux, COMx on Windows)

  • Driver: Kinetis Full-Speed USB Device controller (CONFIG_KINETIS_USBOTG=y)

  • Hardware requirement: Standard Micro-USB cable connected directly to the host PC

Building:

./tools/configure.sh teensy-3.x:usbnsh
make -j$(nproc)
teensy_loader_cli --mcu=mk20dx256 -w -v nuttx.hex  # Use --mcu=mk20dx128 for Teensy 3.0

After flashing and rebooting, connect to the USB serial device:

# Linux
minicom -D /dev/ttyACM0

# Or using picocom
picocom -b 115200 /dev/ttyACM0
