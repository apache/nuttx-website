printf

This page explains what printf() does in NuttX: each conversion, flag, length, width and precision, each option and profile, and the flash and stack that each one costs.

printf(), fprintf(), dprintf(), sprintf(), snprintf(), asprintf(), syslog() and their v forms all use one function: lib_vsprintf() in libs/libc/stream/lib_libvsprintf.c. So this page applies to all of them.

On an output error, printf(), fprintf() and their v forms return a negative value. A buffered stream reports a write error when it flushes.

All outputs on this page come from a run of the examples on NuttX (rv-virt:nsh, 32-bit RISC-V, under QEMU). The first sections show the Full profile. Each example shows the output between quotes.

The rule

A correct call of printf() never crashes or hangs, in any configuration. A correct call is a call that GCC and Clang accept with -Wall -Wextra -Wformat=2.

  • The grammar of the format is always on. An option removes an output, and never the parser.

  • Each argument is read at its right size, also when its conversion is off.

  • A conversion that is off prints one ?, padded to the width, so the rest of the line stays correct. %n always prints nothing.

  • Width and precision counters cannot wrap. No read or write goes outside a buffer. NULL for %s prints (null). The stack use is bounded.

Width

The width is the smallest number of bytes. A longer output is not cut. * takes the width from an int argument, and a negative value means the - flag and a positive width.

printf("%5d", 42)       "   42"
printf("%*d", 5, 42)    "   42"
printf("%*d|", -5, 42)  "42   |"
printf("%5s", "ab")     "   ab"
printf("%-5s|", "ab")   "ab   |"
printf("%3d", 12345)    "12345"

Precision

For an integer, the precision is the smallest number of digits (LIBC_PRINTF_INT_PRECISION). An integer with the value 0 and a precision of 0 prints no digits. For %e, %f and %a it is the number of digits after the point. For %g it is the number of significant digits. For %s it is the largest number of bytes. * takes it from an int argument, and a negative value means no precision.

printf("%.3d", 5)         "005"
printf("%.0d|", 0)        "|"
printf("%8.3d", 5)        "     005"
printf("%.2f", 3.14159)   "3.14"
printf("%.3e", 3.14159)   "3.142e+00"
printf("%.3g", 3.14159)   "3.14"
printf("%.3s", "abcde")   "abc"
printf("%.*f", 1, 2.25)   "2.2"
printf("%.*d|", -1, 0)    "0|"
printf("%8.2f", 3.14159)  "    3.14"
printf("%.0f", 2.5)       "2"

Numbered arguments

%n$ takes argument number n (LIBC_NUMBERED_ARGS), up to LIBC_NL_ARGMAX. *m$ takes a width or precision from argument m. POSIX does not allow a mix of numbered and sequential conversions in one format.

printf("%2$s %1$s", "world", "hello")  "hello world"
printf("%1$*2$d|", 42, 5)              "   42|"
printf("%2$.*1$f", 2, 3.14159)         "3.14"

Each argument before the highest number that the format uses must have a number in the format: otherwise its size is not known, so printf() cannot find the arguments after it. Then it reads only the arguments before the gap, and a conversion with a later number ends the output.

Floating point values

printf("%f", 1.0 / 0.0)        "inf"
printf("%F", -1.0 / 0.0)       "-INF"
printf("%e", 0.0 / 0.0 * 0.0)  "nan"
printf("%f", -0.0)             "-0.000000"
printf("%g", -0.0)             "-0"
printf("%a", -0.0)             "-0x0p+0"
printf("%s", (char *)NULL)     "(null)"
printf("%a", 0.1)              "0x1.999999999999ap-4"
printf("%.0a", 1.5)            "0x2p+0"
printf("%.1a", 1.09375)        "0x1.2p+0"
printf("%a", 5e-324)           "0x0.0000000000001p-1022"
printf("%a", 1.0 / 0.0)        "inf"
printf("%10.3a|", 1.5)         "0x1.800p+0|"
printf("%#.0a", 1.0)           "0x1.p+0"
printf("%010a", 1.5)           "0x001.8p+0"

%a has no limit on precision and takes all digits from the bits of the value. With a precision it rounds to nearest, ties to even. A subnormal value has a first digit of 0 and the exponent of the smallest normal value, as in GNU libc.

Unknown conversions and truncated formats

An unknown conversion has no known argument size. So printf() prints % and the letter, then the rest of the format as text, reads no more arguments, and ends. A format that ends in the middle of a conversion prints % and ends, and no read goes past the terminator. This is always on. A valid C23 format that this configuration does not know takes the same path, so it cannot misread a later %s.

printf("%d %y %d", 1, 2)    "1 %y %d"
printf("a%-5.3kb%d", 1)     "a%kb%d"
printf("abc%")              "abc%"
printf("abc%5")             "abc%"
printf("abc%l")             "abc%"
printf("%Hf|%s", 1.5, "x")  "%Hf|%s"
printf("%w7d|%d", 1, 2)     "%w7d|%d"

Large output

There is no cap on width or precision. %2147483647d is legal and prints all of it, which takes about 2 days on a 115200 baud console. A caller with a small buffer must use snprintf(). If the total passes INT_MAX, the result is -1 with errno set to EOVERFLOW. The output written before that stays. A conversion that is longer than INT_MAX fails before its output. A width or precision with too many digits stops at INT_MAX.

The next examples use snprintf() with a small buffer, and show the return value.

snprintf(buf, sizeof(buf), "x%2147483647d", 1)              returns -1, errno 75 (EOVERFLOW)
snprintf(buf, sizeof(buf), "%.2147483647f", 1.5)            returns -1, errno 75 (EOVERFLOW)
snprintf(buf, sizeof(buf), "%.99999999999s|", "abc")        returns 4
snprintf(buf, sizeof(buf), "%300d", 1)                      returns 300

In Default, LIBC_FLOATINGPOINT is on when DEFAULT_SMALL is off and the CPU has an FPU, as before the profiles existed. In Minimal, LIBC_PRINTF_LONG_LONG stays on with SYSLOG_TIMESTAMP or FS_PROCFS, because the log time stamps and /proc print time_t and uint64_t.

LIBC_PRINTF_HEXFLOAT does not need LIBC_FLOATINGPOINT. It uses no floating point operation and pulls in no soft-float code, so a small board with floating point off can still print the exact value of a double.

LIBC_PRINTF_EXACT prints the correctly rounded digits of each double, ties to even, with no limit on the number of digits. Most values take the same short path as without the option. A value that the short path cannot prove correct takes vsprintf_float_big(), with a larger stack frame. LIBC_PRINTF_EXACT_LDOUBLE does the same for long double, and needs LIBC_PRINTF_EXACT. Its buffer is on the stack of vsprintf_ldouble(), which only %Le, %Lf and %Lg call.

LIBC_PRINTF_PERCENT_N is dangerous. With it, %n stores the count of the bytes so far through its pointer, at the size of its length modifier, and prints nothing. A format that an attacker can change then gives a write to any address. A NULL pointer stores nothing. With it on, the call below stores 2 in n:

printf("ab%n|", &n)  "ab|"

With LIBC_PRINTF_C23 off %b and wN are unknown conversions, so they print as text and end the conversions. Numbered arguments off have the same result.

Correct and wrong usage

If the compiler accepts the call with -Wall -Wextra -Wformat=2, it is correct usage and printf() must handle it. If the compiler warns, it is wrong usage.

These are outside the guarantee, because printf() cannot detect them:

  • A wild pointer for %s.

  • An argument of the wrong type, such as a double for %d or an int for %s.

  • printf(NULL): NULL is not a format string.

  • A mix of numbered and sequential conversions.

  • A wild pointer for %n with LIBC_PRINTF_PERCENT_N on.

What is outside the guarantee

The guarantee is about safety. Without LIBC_PRINTF_EXACT the output of %e, %f and %g is not exact, and some forms do not match the standard yet. Each call below shows the output of Default, and of Full with the exact options on:

printf("%.0f", 0.5)
  Default: "0"
  Exact:   "0"
printf("%.0f", 2.5)
  Default: "2"
  Exact:   "2"
printf("%.2f", 1.005)
  Default: "1.00"
  Exact:   "1.00"
printf("%.0f", 1e22)
  Default: "10000000000000000000000"
  Exact:   "10000000000000000000000"
printf("%.20f", 0.1)
  Default: "0.10000000000000001000"
  Exact:   "0.10000000000000000555"
printf("%.17e", 0.1)
  Default: "1.00000000000000010e-01"
  Exact:   "1.00000000000000006e-01"
printf("%.25e", 1e23)
  Default: "9.9999999999999992000000000e+22"
  Exact:   "9.9999999999999991611392000e+22"
printf("%g", 1234567.0)
  Default: "1.23457e+06"
  Exact:   "1.23457e+06"
printf("%#g", 1.0)
  Default: "1.00000"
  Exact:   "1.00000"
printf("%.30Le", 0.1L)
  Default: "1.000000000000000100000000000000e-01"
  Exact:   "1.000000000000000000000000000000e-01"

  • Without LIBC_PRINTF_EXACT, %e, %f and %g have at most 17 significant digits. The digits after them print as 0. The last digits can differ from a correctly rounded result.

  • Without LIBC_PRINTF_EXACT_LDOUBLE, %Le, %Lf and %Lg have the precision and the range of a double.

  • %lc and %ls without LIBC_LOCALE print narrow characters.

  • dprintf() returns the length of the output also when the write fails.

  • lib_bsprintf() has its own smaller format: see lib_bsprintf.

Floating point is off by default on the two Cortex boards, and on by default on the other two. Full has it on everywhere.

%e, %f and %g use integer operations only, and pull in no soft-float code. Other code in the image can: see the row of libgcc. %lld needs a 64-bit division on a 32-bit CPU, and the kernel clock code often needs it too.

LIBC_NUMBERED_ARGS also adds a variable length array to the stack of lib_vsprintf(): one union for each argument that the format uses. The size of the union is 8 bytes, or the size of long double with LIBC_PRINTF_HEXFLOAT on a CPU where that is larger.
