Nanopower nPZero G1S power-saving IC

The nPZero G1S (NPZG1SQ32) from Nanopower Semiconductor is a power-saving IC for sensor systems. While the host MCU is powered, the nPZero is an I2C slave of the host (Standby state). When the host sends the Idle command, the nPZero switches the host off and polls up to four I2C or SPI peripherals by itself, powering them, sending them initialization commands from its 128-byte SRAM, reading their values and comparing them with thresholds. When a wake-up condition happens, it switches the host on again. The wake-up conditions are:

  • a peripheral value inside the trigger area, or an interrupt of a peripheral,

  • a VBAT or ADC_IN value outside the ADC thresholds,

  • a NAK of an I2C peripheral (if enabled),

  • the global time-out.

So the host boots at each wake-up. The usual program reads the wake-up reason, handles it, sends the configuration and enters Idle state again.

The driver (drivers/power/supply/npzero.c) is a character driver controlled with ioctl() commands. The register map, the values of the fields and the commands are in include/nuttx/power/npzero.h.

Configuration

  • CONFIG_NPZERO: enables the driver. It needs CONFIG_I2C.

  • CONFIG_NPZERO_I2C_FREQUENCY: I2C frequency, 100 kHz by default. The nPZero supports the I2C standard mode only.

Board interface

The board registers the driver with:

int npzero_register(FAR const char *devpath, FAR struct i2c_master_s *i2c,
                    uint8_t addr);

addr is the 7-bit I2C address, NPZERO_I2C_ADDR (0x3d). The function reads the ID register and returns -ENODEV if it is not NPZERO_ID (0x60). Since the host is switched off in Idle state, it must be called at each boot, for instance from board_late_initialize():

#include <nuttx/power/npzero.h>

i2c = stm32_i2cbus_initialize(1);
ret = npzero_register("/dev/npzero0", i2c, NPZERO_I2C_ADDR);

Shared I2C bus

The I2C bus of the host is also the bus of the I2C peripherals, and the peripherals are usually powered by the SW_LP switches of the nPZero. After a reset of the nPZero (power-on, brown-out, RSTN or soft reset), all the peripheral switches are off. An unpowered peripheral can load SDA through its protection diodes, which then rises too slowly for the I2C controller of the host.

On the nPZero G1S Development Kit, an unpowered AS6212 temperature sensor board makes SDA rise in about 10 us (100 us when SCL is low): the STM32 I2C controller reports an arbitration loss and npzero_register() fails with -EAGAIN. The Nanopower firmware fails in the same way. So:

  • Set the pswint bits of the I2C peripherals in the configuration, so that they stay powered while the host is on (Standby state).

  • After a reset of the nPZero, the board must enable these switches (PSWCTL) before it talks to the nPZero at 100 kHz. The npzero-g1s-dk board does it with a slow bit-banged I2C transfer, see Nanopower nPZero G1S DevKit (STM32).

  • Do not plug a sensor board while the host is running.

Errata

The driver applies the workarounds of the errata NPZ-G1S-ERRATA-V3.0:

  • #2, sequential SRAM writes can corrupt the SRAM: NPZEROIOC_CONFIGURE writes the whole SRAM one byte at a time, in the order of the workaround. NPZEROIOC_WRITEREG refuses the SRAM addresses (-EACCES).

  • #11, incorrect IREF trim values (unexpected reset in Idle state): npzero_register() corrects the trim values when no wake-up flag is set in STA1 and STA2, that is after a reset of the nPZero.

The other errata are for the application:

  • #3: an interrupt pulse shorter than 2.5 us wakes the nPZero up without setting its FP bit in STA2.

  • #4: after a NAK (FNAKP bit in STA2) or an interrupt time-out, the VALP registers of a peripheral may keep the value of another peripheral.

  • #5: only the soft reset bit (NPZERO_STA1_RSTSRC_SOFT) of the reset source is reliable.

  • #6, #7: for an 8-bit value, two bytes are read from the peripheral.

  • #9: with the ADC_IN wake-up enabled, ADC_IN must stay between 600 mV and VBAT.

The datasheet also forbids the peripheral power switch mode 0 (switch with output voltage rise detection), which can lock up the polling, so the driver refuses it.

Status

struct npzero_status_s holds the raw sta1 and sta2 registers. Use the NPZERO_STA1_* bits (FTOUT global time-out, FA1 VBAT trigger, FA2 ADC_IN trigger, RSTSRC reset source) and the NPZERO_STA2_FP(n) (trigger) and NPZERO_STA2_FNAKP(n) (NAK) bits of peripheral n.

NPZEROIOC_GETVALUE returns the 16-bit value of the peripheral periph (1 to 4) in the type set by its dtype. NPZEROIOC_GETADC returns the ADC codes, see the table ADC codes of the datasheet. The codes of the VBAT channel are the ones of the ADC_IN channel minus 0x20.

Example

Configuration of the AS6212 temperature sensor of the DevKit on peripheral 4, which wakes the host up above 25 C or below 10 C:

static const uint8_t g_init[] =
{
  0x01, 0x82, 0x02, 0xa0
};

static const struct npzero_periph_s g_temp =
{
  .pwmod    = NPZERO_PWMOD_PERIODIC,
  .tmod     = NPZERO_TMOD_READ,
  .pswmod   = NPZERO_PSWMOD_LOGIC,
  .dtype    = NPZERO_DTYPE_INT16,
  .seqrw    = true,
  .swap     = true,
  .addr     = 0x49,
  .rreg     = 0x00,
  .period   = 300,                /* 30 s with the 10 Hz clock */
  .throver  = 25 * 128,
  .thrunder = 10 * 128,
  .twtp     = 49,
  .tinit    = NPZERO_WAIT_256,
  .twait    = NPZERO_WAIT_256,
  .ninit    = sizeof(g_init) / 2,
  .init     = g_init,
};

static const struct npzero_config_s g_config =
{
  .hostmode = NPZERO_HOSTMODE_LOGIC,
  .pswint   = 1 << 3,
  .wakeup   = NPZERO_SYSCFG1_WUP_P(4),
  .sclkdiv  = NPZERO_SCLKDIV_1,
  .i2cpull  = NPZERO_I2CPULL_AUTO,
  .timeout  = 3000,               /* 300 s */
  .periph   =
  {
    NULL, NULL, NULL, &g_temp
  },
};

fd = open("/dev/npzero0", O_RDWR);
ioctl(fd, NPZEROIOC_GETSTATUS, (unsigned long)&status);
if (status.sta2 & NPZERO_STA2_FP(4))
  {
    value.periph = 4;
    ioctl(fd, NPZEROIOC_GETVALUE, (unsigned long)&value);
  }

ioctl(fd, NPZEROIOC_CONFIGURE, (unsigned long)&g_config);
ioctl(fd, NPZEROIOC_IDLE, 0);    /* The host is switched off */

The complete example is apps/examples/npzero, see npzero nPZero G1S power-saving example, and the board is Nanopower nPZero G1S DevKit (STM32).

Differences with the Nanopower driver API

The driver follows the datasheet NPZ-G1S-DS-V1.0 where the Nanopower driver API does not:

  • The host switch mode “power switch” is 0, the value 1 is invalid.

  • The reset source is 4 bits (bit 3 is the soft reset) and the odd bits of STA2 are the NAK flags of the peripherals, not time-out flags.

  • The ADC clocks derived from the crystal need NPZERO_SCLK_XO.

  • gateboost is written, and no ADC channel configuration is needed.

  • The SRAM is written once, in 128 single writes, instead of 128 writes for each byte.

  • tinit and twait are named after the TINIT and TWT fields of TCFGP. pre_wait_time of the Nanopower API sets TWT.
